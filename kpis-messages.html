Methodology · KPIs & Signalling

Lab Validation KPIs & Signalling Messages

For every test case I validate two things in parallel: the KPIs (the counters that say whether a feature performs) and the signalling messages (the protocol exchange that proves it works correctly). Watching both together is what separates "the call connected" from "the call connected for the right reasons" — and it's how I confirm feature compliance before anything reaches the field.

The signalling fingerprint of each feature

Attach
RRC Setup → NAS Registration → Auth → Security Mode → Registration Accept → PDU Session Establishment Confirms the UE registers, gets a security context, and obtains an IP/QoS flow. Full attach page →
Data
PDU Session Establishment + GTP-U (UDP 2152) user-plane Confirms the bearer/QoS flow is up and user data flows through the UPF tunnel. I read 5QI/ARP, S-NSSAI, UPF IP and TEID from the establishment message.
Voice
SIP REGISTER → 200 OK; INVITE → 180 Ringing → 200 OK → ACK; RTP UL/DL Confirms IMS registration and a working VoNR/VoLTE call. I measure setup time from INVITE → 180 Ringing. Voice page →
Mobility
Measurement Report → Handover (Xn/NG) → RRCReconfiguration → Complete Confirms seamless mobility with service continuity. Xn / NG pages.
CA+EN-DC
RRCReconfiguration with SCell / SCG addition Confirms multi-cell / multi-RAT capacity boost via Carrier Aggregation (SCell add, intra-RAT) or EN-DC (SCG add, LTE anchor + NR secondary); I verify throughput uplift in iPerf and OAM counters.

How I read it from the trace

I correlate OAM counters (the KPI view) with the packet trace (the signalling view) using Wireshark and XCAL5. From the trace I confirm MIB/SIB1/SIB2, authentication and security mode, then the per-feature messages above — pulling the protocol layer involved (PHY/MAC/RLC/PDCP/RRC on the radio side, HARQ/ARQ for retransmission behaviour, NGAP/NAS on the core side). When a KPI dips, the trace tells me why; when the trace looks clean, the KPI tells me whether it's good enough to ship. My Python/tshark automation turns this correlation into a repeatable PASS/FAIL.

Field notes

  • KPI without signalling is blind. A passing success-rate can still hide a non-compliant message sequence.
  • Signalling without KPI is incomplete. A clean trace over 10 minutes doesn't prove stability over 24 hours.
  • Know the message that carries the field. 5QI/ARP/slice live in the PDU Session Establishment; establishment cause lives in RRC setup.
