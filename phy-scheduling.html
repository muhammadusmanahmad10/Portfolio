5G NR PHY & Scheduling

The 5G air interface is OFDM with flexible numerology, beam-based access, and a scheduler that hands out resources slot-by-slot. This page covers the physical layer (frame structure, channels, reference signals, beam management) and the MAC scheduling, HARQ and link-adaptation behaviour that sit on top — the parameters that determine real throughput and reliability.

💡Formulas to remember: SCS = 15×2μ kHz, slot length = 1/2μ ms, slots per subframe = 2μ. Constants for normal CP: 14 OFDM symbols per slot, 12 subcarriers per Resource Block (RB). So one RB occupies 12 × SCS in frequency (e.g. 180 kHz at 15 kHz SCS, 360 kHz at 30 kHz, 720 kHz at 60 kHz, …).

Total RBs in the cell bandwidth: the number of RBs has to fit inside the cell’s channel bandwidth. Roughly: RBs ≈ usable BW / (12 × SCS). For example at 30 kHz SCS one RB is 360 kHz, so a 100 MHz NR cell carries up to ~273 RBs in DL. Not every RB at the band edge is usable — some are reserved as guard band on each side to keep the cell from leaking into adjacent operators / channels and to give the filter some margin. So a "100 MHz" cell really transmits on slightly less than 100 MHz of subcarriers; the rest is intentionally left unused for spectral cleanliness.

Bandwidth Parts (BWP): the cell’s bandwidth is split into one or more BWPs, and the UE operates on one active BWP per direction at a time. Why do this?

  • Battery saving: when the UE isn’t pushing big traffic, it can sit on a small BWP and use a narrower receiver instead of decoding the full 100 MHz — significantly less power.
  • UE-capability matching: if the cell is 100 MHz wide but the UE only supports a smaller bandwidth (e.g. 20 / 40 MHz), the UE can still attach by being given a BWP that fits inside its capability. The cell stays wide for capable UEs while narrower UEs operate on a smaller BWP of the same cell.
  • Numerology / service split: different BWPs can use different SCS, so the same cell can carry an eMBB BWP and a URLLC BWP side by side.
This is what the BWPS attach issue was about.

Why channel coding and modulation? Radio links are noisy, so the transmitter codes the bits first — adding redundancy so the receiver can detect and correct errors. The coded bits are then modulated, i.e. mapped onto a constellation point (phase + amplitude) that can actually be carried on a radio waveform. Coding makes the link robust to noise; modulation lets the bits ride the air interface. Together they let real user data survive the trip through the channel.

Putting the pieces together, here is the chain from a single user-data bit to a radio-frame on the air interface:

bits  →  (channel coding: LDPC for data / Polar for control)  →  coded bits
      →  (modulation: QPSK / 16-QAM / 64-QAM / 256-QAM / 1024-QAM)  →  modulation symbols
      →  mapped onto Resource Elements (1 RE = 1 subcarrier × 1 OFDM symbol)
      →  12 subcarriers form 1 Resource Block (RB)
      →  RBs are scheduled across 14 OFDM symbols = 1 slot
      →  2μ slots form 1 subframe = 1 ms
      →  10 subframes form 1 radio frame = 10 ms

So one RB × one slot (normal CP) = 12 × 14 = 168 REs of capacity. Multiply by the modulation order, the code rate and the number of MIMO layers (rank), and you have the per-slot transport-block size. This is exactly the calculation MCS encodes — an MCS index selects (modulation, code rate) and the scheduler picks one per UE per slot to hit the BLER target.

Throughput formula: Throughput = NRB × 12 × Nsym × Qm × R × Nlayers × Nslots/sec × (1 − OH) × TDDratio. Using this formula we calculate throughput.

Putting the same idea in everyday language: bits are mapped into modulation symbols, symbols are transmitted on subcarriers, 12 subcarriers form one Resource Block (RB), RBs are scheduled over time in slots, slots form subframes, and 10 subframes form one 10 ms radio frame. Each level of the stack is just a way to package the level below it — the smallest unit is one bit on one subcarrier in one OFDM symbol (a Resource Element), and the largest unit handed to the air interface is the 10 ms radio frame.

  1. Bits → symbols. After LDPC encoding, groups of bits are mapped onto a constellation point — 2 bits per QPSK symbol, 4 bits per 16-QAM, 6 per 64-QAM, 8 per 256-QAM, 10 per 1024-QAM. Higher modulation = more bits per symbol but needs better SINR.
  2. Symbols → subcarriers. Each modulation symbol is carried on one subcarrier during one OFDM symbol period. That smallest tile is a Resource Element (RE).
  3. Subcarriers → Resource Block. 12 contiguous subcarriers are grouped into one RB (180 kHz at 15 kHz SCS, 360 kHz at 30 kHz, and so on).
  4. RBs → slot. The scheduler allocates RBs to a UE across 14 OFDM symbols, which makes one slot. The slot is the unit the gNB scheduler hands out, slot-by-slot, via PDCCH.
  5. Slots → subframe. A subframe is always 1 ms. It holds 2μ slots — so 1 slot at 15 kHz SCS, 2 slots at 30 kHz, 4 at 60 kHz, etc.
  6. Subframes → radio frame. 10 subframes = a 10 ms radio frame. This is the master timing unit the UE locks to via the SSB.

SSB — PSS, SSS and how PCI is computed

The SSB (Synchronization Signal Block) carries two synchronization signals plus the PBCH. From these the UE derives the cell's Physical Cell ID (PCI):

SignalCarriesRange
PSS (Primary Sync Signal)NID(2) — the cell-ID group index within the group0, 1, 2 (3 values)
SSS (Secondary Sync Signal)NID(1) — the cell-ID group0 … 335 (336 values)

PCI formula (NR):

NIDcell  =  3 × NID(1)  +  NID(2)

Total unique PCIs in NR = 3 × 336 = 1008   (PCI range 0–1007)

(For reference, LTE had 504 PCIs — 3×168 — using the same construction with a smaller NID(1) range.) The PBCH inside the SSB carries the MIB; the UE then reads SIB1 to camp on the cell. PCI planning assigns these IDs across the network so neighbours don't collide (same PCI).

Physical channels — what each one is

Channel (full form)DirectionPurpose
SSB — Synchronization Signal Block (carries PSS / SSS / PBCH)DL broadcastThe first signal a UE looks for when it powers on. PSS / SSS let the UE find the cell and learn its Physical Cell ID; PBCH carries the MIB. After successfully decoding the SSB, the UE can proceed to read the SIBs and initiate network access.
PDCCH — Physical Downlink Control ChannelDLThe gNB’s "loudspeaker" telling each UE when and where to read its downlink data, or when and where to send uplink data. The message inside is called DCI (Downlink Control Information) and acts as the scheduling grant.
PDSCH — Physical Downlink Shared ChannelDLThe actual downlink user data (web, voice, video, files) — transmitted on the time/frequency resources that the PDCCH just pointed the UE to.
PUCCH — Physical Uplink Control ChannelULThe UE’s small uplink control channel for feedback to the gNB: HARQ ACK/NACK ("did I receive the last block?"), CSI reports ("here is the channel quality I see") and SR ("please give me uplink resources").
PUSCH — Physical Uplink Shared ChannelULThe actual uplink user data from the UE to the gNB (and small control info when piggy-backed on top).
PRACH — Physical Random Access ChannelULHow a UE says "hello" to the network when it has no scheduling resources yet — used for initial access, handover, and beam-failure recovery. It carries a preamble (one of 64 Zadoff-Chu sequences) that triggers the random-access response.

RACH procedure — 4-step and 2-step

Reference signals — how the link is measured

Reference signals are known patterns the transmitter sends so the receiver can “calibrate” against them — estimate the channel, judge its quality, sound the channel, or work out where the UE is. Different signals serve different jobs:

Signal (full form)Purpose
DM-RS — Demodulation Reference SignalA known pattern sent alongside each data / control transmission (PDSCH / PDCCH / PUSCH / PUCCH) so the receiver can estimate the channel right where the data is — and demodulate it correctly.
CSI-RS — Channel State Information Reference SignalA downlink "test tone" the gNB sends so the UE can measure how good the channel currently is and report back. The three things the UE feeds back are:
  • CQI (Channel Quality Indicator) — a 0–15 number that says "this is the modulation + code rate I can decode at the moment". Drives the MCS the scheduler picks.
  • RI (Rank Indicator) — how many parallel MIMO layers the channel can carry right now (1, 2, 4…). More layers = more throughput, if the channel supports it.
  • PMI (Precoding Matrix Indicator) — the UE’s suggested precoder from a standardised codebook — basically "shape the beam this way so I hear you best."
MIMO precoding = the gNB combines its multiple antennas with weighted phases / amplitudes (the precoder) so the signal forms a constructive beam at the UE. PMI is the UE’s recommendation for which precoder to use; the gNB can follow it (closed-loop MIMO) for maximum receive quality.
SRS — Sounding Reference SignalThe uplink version — the UE sends a known signal so the gNB can sound the UE’s uplink channel: used for UL scheduling, picking the best UL beam, and (in TDD) inferring the DL channel from the UL measurement for MIMO precoding (channel reciprocity).
PT-RS — Phase-Tracking Reference SignalA small reference that helps the receiver track phase noise drift over time within a slot — mostly relevant at mmWave (FR2), where local-oscillator phase noise is large.
PRS — Positioning Reference SignalA downlink signal designed for positioning — the UE measures PRS from multiple cells and the LMF turns those measurements into a location fix (used for E911).

Beam management (FR2 & FR1 Massive MIMO)

5G is beam-based: the gNB sweeps multiple SSB beams for cell access and then refines to user-specific beams via CSI-RS reports. 3GPP describes beam management as four logical steps that run continuously while the UE is connected:

StageWhat it doesHow it works
1. Beam SweepingThe transmitter sends the same signal in a sequence of narrow beams covering its angular range, so a receiver anywhere in the cell can find at least one good beam.gNB sweeps SSB beams within the SSB burst set (up to 4 / 8 / 64 SSBs in FR1-low / FR1-high / FR2). For refinement it sweeps CSI-RS resources; the UE can also sweep its own Rx beams.
2. Beam MeasurementThe receiver measures the quality of each swept beam.UE measures SS-RSRP / SS-RSRQ / SS-SINR per SSB and CSI-RSRP / CSI-RSRQ / CSI-SINR per CSI-RS resource, per the configured CSI-ReportConfig.
3. Beam Determination (Beam Selection)The best beam (or set of beams) is selected for use on the link.The gNB selects the serving Tx beam from the UE's report and signals it via TCI state (PDCCH/PDSCH spatial relation). The UE, in parallel, picks the best Rx beam during its own sweep (P-3).
4. Beam ReportingThe UE feeds the measurements back so the gNB can choose / switch beams.The UE measures the signal quality of different beams and reports the best ones to the gNB, including their signal strength (RSRP) and quality (SINR). The gNB uses these reports to decide which beam should serve the UE, when to switch beams, and to detect beam failures.

These four stages map onto the classic P-1 / P-2 / P-3 procedures:

  1. P-1 — Initial beam pairing over the SSB sweep (UE measures SS-RSRP and picks the best beam pair for initial access).
  2. P-2 — gNB-side Tx-beam refinement using a CSI-RS sweep within the best SSB beam.
  3. P-3 — UE-side Rx-beam refinement on a fixed gNB Tx beam.
  4. Beam-failure detection & recovery (BFD/BFR) — UE declares beam failure on consecutive bad-quality measurements and recovers via a new beam through a dedicated PRACH resource (CFRA).

This connects directly to my Massive MIMO work — beamforming gains depend on CSI feedback quality and the right beam-management configuration.

MCS vs SINR — quick reference

The UE measures SINR, maps it to a CQI (0–15) and reports it; the gNB picks an MCS from the active table aiming at ~10% BLER. Rough mapping I use as a sanity-check during throughput validation:

SINR (dB, approx.)CQIModulationOperating regime
< −60—Out of range — UE can’t decode
−6 … 01–3QPSKCell edge / weak coverage
0 … 64–6QPSKMarginal → best QPSK
6 … 127–916-QAMGood mid-cell
12 … 2010–1264-QAMNear-cell / good RF
> 2013–1564-QAM (or 256-QAM if enabled)Excellent RF

With the 256-QAM CQI table (TS 38.214) enabled, the highest channel quality level (CQI 15) can carry much more data using the same radio spectrum. The scheduler then adjusts MCS per TTI (Transmission Time Interval) based on the CQI, outer-loop link adaptation (OLLA) using ACK/NACK history, and HARQ retransmissions.

💡Rule of thumb: clean SINR ≥ 20 dB but MCS stuck around 20–22 usually means the 256-QAM table isn’t enabled, the UE capability doesn’t support it, or OLLA has backed off after a BLER spike.

FR2 (mmWave) — what's different

FR2 spans 24.25–71 GHz (e.g. n257, n258, n260, n261, plus Rel-17 extensions to 52.6–71 GHz). The fundamentals shift:

  • Beam-based everything. Cells are made of narrow beams; SSB sweep and beam refinement (CSI-RS/SRS) drive initial access and serving-beam selection. Beam-failure detection (BFD) and recovery (BFR) over a dedicated PRACH resource are essential.
  • Very high path loss + atmospheric/rain absorption — coverage is small and directional, hand-blocking matters.
  • Higher SCS — 60 kHz / 120 kHz numerology gives shorter slots so the scheduler can react to fast channel changes.
  • PT-RS (phase-tracking reference signal) compensates phase noise at these frequencies.
  • Bigger bandwidth per carrier (100 MHz+ common, hundreds of MHz aggregated) — feeds raw throughput.

My deployment work is FR1 (n41/n77 and the L-bands); FR2 is included here for completeness because it shares the same numerology / scheduler / beam-management framework on top of very different RF conditions.

How I use PHY/scheduling in validation

When throughput, latency or coverage misbehave, the PHY/scheduling layer often holds the real story:

  • Throughput plateau: check reported CQI/MCS — a clamped MCS points to RF or scheduler config, not transport.
  • High latency under load: check HARQ retx rate and DRX configuration; PDCCH congestion can starve users.
  • Coverage edge: SSB RSRP & beam-failure events; RF optimization (tilt/power) then closes the gap.
  • VoNR call quality: SPS / configured-grant config and 5QI 1 mapping; voice page.
