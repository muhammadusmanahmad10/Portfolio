5G NR PHY & Scheduling

The 5G air interface is OFDM with flexible numerology, beam-based access, and a scheduler that hands out resources slot-by-slot. This page covers the physical layer (frame structure, channels, reference signals, beam management) and the MAC scheduling, HARQ and link-adaptation behaviour that sit on top — the parameters that determine real throughput and reliability.

💡Formulas to remember: SCS = 15×2μ kHz, slot length = 1/2μ ms, slots per subframe = 2μ. Constants for normal CP: 14 OFDM symbols per slot, 12 subcarriers per Resource Block (RB). So one RB occupies 12 × SCS in frequency (e.g. 180 kHz at 15 kHz SCS, 360 kHz at 30 kHz, 720 kHz at 60 kHz, ...).

Bandwidth Parts (BWP): the cell's bandwidth is split into one or more BWPs; the UE operates on one active BWP per direction at a time. This is what the BWPS attach issue was about.

How bits become a transmission — the hierarchy

Putting the pieces together, here is the chain from a single user-data bit to a radio-frame on the air interface:

bits  →  (channel coding: LDPC for data / Polar for control)  →  coded bits
      →  (modulation: QPSK / 16-QAM / 64-QAM / 256-QAM / 1024-QAM)  →  modulation symbols
      →  mapped onto Resource Elements (1 RE = 1 subcarrier × 1 OFDM symbol)
      →  12 subcarriers form 1 Resource Block (RB)
      →  RBs are scheduled across 14 OFDM symbols = 1 slot
      →  2μ slots form 1 subframe = 1 ms
      →  10 subframes form 1 radio frame = 10 ms

So one RB × one slot (normal CP) = 12 × 14 = 168 REs of capacity. Multiply by the modulation order, the code rate and the number of MIMO layers (rank), and you have the per-slot transport-block size. This is exactly the calculation MCS encodes — an MCS index selects (modulation, code rate) and the scheduler picks one per UE per slot to hit the BLER target.

In plain words — the time/frequency hierarchy

Putting the same idea in everyday language: bits are mapped into modulation symbols, symbols are transmitted on subcarriers, 12 subcarriers form one Resource Block (RB), RBs are scheduled over time in slots, slots form subframes, and 10 subframes form one 10 ms radio frame. Each level of the stack is just a way to package the level below it — the smallest unit is one bit on one subcarrier in one OFDM symbol (a Resource Element), and the largest unit handed to the air interface is the 10 ms radio frame.

  1. Bits → symbols. After LDPC encoding, groups of bits are mapped onto a constellation point — 2 bits per QPSK symbol, 4 bits per 16-QAM, 6 per 64-QAM, 8 per 256-QAM, 10 per 1024-QAM. Higher modulation = more bits per symbol but needs better SINR.
  2. Symbols → subcarriers. Each modulation symbol is carried on one subcarrier during one OFDM symbol period. That smallest tile is a Resource Element (RE).
  3. Subcarriers → Resource Block. 12 contiguous subcarriers are grouped into one RB (180 kHz at 15 kHz SCS, 360 kHz at 30 kHz, and so on).
  4. RBs → slot. The scheduler allocates RBs to a UE across 14 OFDM symbols, which makes one slot. The slot is the unit the gNB scheduler hands out, slot-by-slot, via PDCCH.
  5. Slots → subframe. A subframe is always 1 ms. It holds 2μ slots — so 1 slot at 15 kHz SCS, 2 slots at 30 kHz, 4 at 60 kHz, etc.
  6. Subframes → radio frame. 10 subframes = a 10 ms radio frame. This is the master timing unit the UE locks to via the SSB.

SSB — PSS, SSS and how PCI is computed

The SSB (Synchronization Signal Block) carries two synchronization signals plus the PBCH. From these the UE derives the cell's Physical Cell ID (PCI):

SignalCarriesRange
PSS (Primary Sync Signal)NID(2) — the cell-ID group index within the group0, 1, 2 (3 values)
SSS (Secondary Sync Signal)NID(1) — the cell-ID group0 … 335 (336 values)

PCI formula (NR):

NIDcell  =  3 × NID(1)  +  NID(2)

Total unique PCIs in NR = 3 × 336 = 1008   (PCI range 0–1007)

(For reference, LTE had 504 PCIs — 3×168 — using the same construction with a smaller NID(1) range.) The PBCH inside the SSB carries the MIB; the UE then reads SIB1 to camp on the cell. PCI planning assigns these IDs across the network so neighbours don't collide (same PCI) or confuse (modulo-3 PSS conflict, which corrupts DM-RS).

Beam management (FR2 & FR1 Massive MIMO)

5G is beam-based: the gNB sweeps multiple SSB beams for cell access and then refines to user-specific beams via CSI-RS reports. 3GPP describes beam management as four logical steps that run continuously while the UE is connected:

StageWhat it doesHow it works
1. Beam SweepingThe transmitter sends the same signal in a sequence of narrow beams covering its angular range, so a receiver anywhere in the cell can find at least one good beam.gNB sweeps SSB beams within the SSB burst set (up to 4 / 8 / 64 SSBs in FR1-low / FR1-high / FR2). For refinement it sweeps CSI-RS resources; the UE can also sweep its own Rx beams.
2. Beam MeasurementThe receiver measures the quality of each swept beam.UE measures SS-RSRP / SS-RSRQ / SS-SINR per SSB and CSI-RSRP / CSI-RSRQ / CSI-SINR per CSI-RS resource, per the configured CSI-ReportConfig.
3. Beam Determination (Beam Selection)The best beam (or set of beams) is selected for use on the link.The gNB selects the serving Tx beam from the UE's report and signals it via TCI state (PDCCH/PDSCH spatial relation). The UE, in parallel, picks the best Rx beam during its own sweep (P-3).
4. Beam ReportingThe UE feeds the measurements back so the gNB can choose / switch beams.UE reports the N best SSB / CSI-RS indices + their RSRP/SINR over PUCCH (periodic / semi-persistent) or PUSCH (aperiodic, triggered by DCI). Reports drive serving-beam updates, beam switching and BFD.

These four stages map onto the classic P-1 / P-2 / P-3 procedures:

  1. P-1 — Initial beam pairing over the SSB sweep (UE measures SS-RSRP and picks the best beam pair for initial access).
  2. P-2 — gNB-side Tx-beam refinement using a CSI-RS sweep within the best SSB beam.
  3. P-3 — UE-side Rx-beam refinement on a fixed gNB Tx beam.
  4. Beam-failure detection & recovery (BFD/BFR) — UE declares beam failure on consecutive bad-quality measurements and recovers via a new beam through a dedicated PRACH resource (CFRA).

This connects directly to my Massive MIMO work — beamforming gains depend on CSI feedback quality and the right beam-management configuration.

MCS vs SINR — what the scheduler picks at each channel quality

Link adaptation is the loop that ties UE-reported channel quality to the modulation and coding the scheduler actually uses. The UE measures SINR on CSI-RS / DM-RS / SSB; it maps that to a CQI (0–15) and reports it; the gNB then picks an MCS index from the active MCS table to land near the ~10% BLER target after the first transmission. 💡Validation rule of thumb I use: if a UE reports clean SINR ≥ 20 dB but MCS stays clamped around 20–22, something is wrong — usually the 256-QAM table isn’t enabled, the UE capability says it doesn’t support it, or OLLA has backed off after a BLER spike. The throughput / stress page walks through the iPerf / Ookla cases where this exact mismatch was the root cause.

RACH procedure — 4-step and 2-step

Random Access (RACH) is how a UE initially synchronises, gets timing advance, and obtains a C-RNTI. NR supports two procedures:

Step4-step RACH (Rel-15+)2-step RACH (Rel-16+)
Msg1
(MsgA in 2-step)		Preamble on PRACH — UE picks one of 64 preamble sequences (Zadoff-Chu root sequences), transmitted on a configured PRACH occasion.Preamble + small payload (PUSCH) combined in MsgA — saves the round-trip of separate Msg1/Msg3.
Msg2
(MsgB in 2-step)		RAR (Random Access Response) on PDSCH, scrambled with RA-RNTI (computed from the PRACH time/freq resource). Carries Timing Advance + UL grant for Msg3 + a TC-RNTI.RAR + contention resolution combined — if successful, UE goes straight to RRC_CONNECTED.
Msg3RRC Setup Request (or similar) on PUSCH using the UL grant from Msg2 — UE identifies itself.— (folded into MsgA)
Msg4Contention Resolution + RRC Setup — the gNB confirms which UE "won" the preamble and promotes TC-RNTI → C-RNTI.— (folded into MsgB)

Preamble (Msg1) details:

  • 64 preamble sequences per cell, generated from Zadoff-Chu root sequences (cell-specific Root Sequence Index).
  • Beam-failure recovery (BFR) uses a dedicated PRACH resource (CFRA — contention-free RA) so the UE recovers without contention.

FR2 (mmWave) — what's different

FR2 spans 24.25–71 GHz (e.g. n257, n258, n260, n261, plus Rel-17 extensions to 52.6–71 GHz). The fundamentals shift:

  • Beam-based everything. Cells are made of narrow beams; SSB sweep and beam refinement (CSI-RS/SRS) drive initial access and serving-beam selection. Beam-failure detection (BFD) and recovery (BFR) over a dedicated PRACH resource are essential.
  • Very high path loss + atmospheric/rain absorption — coverage is small and directional, hand-blocking matters.
  • Higher SCS — 60 kHz / 120 kHz numerology gives shorter slots so the scheduler can react to fast channel changes.
  • PT-RS (phase-tracking reference signal) compensates phase noise at these frequencies.
  • Bigger bandwidth per carrier (100 MHz+ common, hundreds of MHz aggregated) — feeds raw throughput.

My deployment work is FR1 (n41/n77 and the L-bands); FR2 is included here for completeness because it shares the same numerology / scheduler / beam-management framework on top of very different RF conditions.

How I use PHY/scheduling in validation

When throughput, latency or coverage misbehave, the PHY/scheduling layer often holds the real story:

  • Throughput plateau: check reported CQI/MCS — a clamped MCS points to RF or scheduler config, not transport.
  • High latency under load: check HARQ retx rate and DRX configuration; PDCCH congestion can starve users.
  • Coverage edge: SSB RSRP & beam-failure events; RF optimization (tilt/power) then closes the gap.
  • VoNR call quality: SPS / configured-grant config and 5QI 1 mapping; voice page.
