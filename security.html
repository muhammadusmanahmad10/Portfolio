5G / Telecom Security

Security in a mobile network runs from the SIM to the core. I work hands-on with the transport-security layer every day (IPsec/IKEv2 tunnels, certificate-based authentication, traffic selectors), and I understand the wider 5G security architecture — mutual authentication, key hierarchy, subscriber-identity protection and integrity/ciphering — that protects the air interface and the signalling behind it.

Where security sits in the 5G stack

Each layer protects a different thing: SUCI hides the permanent identity over the air; 5G-AKA proves UE and network to each other and derives keys; NAS/AS security ciphers and integrity-protects signalling and data; and IPsec protects the backhaul/interface transport to the core.

The wider 5G security architecture (TS 33.501)

MechanismWhat it protects / how
SUPI / SUCIThe permanent subscriber identity (SUPI) is never sent in clear over the air — it's encrypted into a SUCI using the home network public key, defeating IMSI-catchers.
5G-AKA / EAP-AKA'Mutual authentication between UE and network via AUSF/UDM; produces the anchor key and the key hierarchy (K → K_AUSF → K_SEAF → K_AMF → K_gNB).
NAS securityCiphering + integrity protection of NAS signalling between UE and AMF (activated at Security Mode Command).
AS securityCiphering + integrity of RRC signalling and user-plane between UE and gNB (keys derived from K_gNB; horizontal/vertical key derivation on handover).
AlgorithmsNEA/NIA (encryption/integrity) — e.g. AES, SNOW 3G, ZUC based.
Network domain securityIPsec/IKEv2 + PKI between network nodes (TS 33.310) — the layer I operate hands-on.

Field notes

  • Identity is protected before authentication. SUCI conceals SUPI on the very first message.
  • Keys are derived, not shared. The hierarchy means a compromised gNB key doesn't expose the anchor key.
  • Transport security is its own failure domain. A cert/IKE/ACL fault stops service even when the radio is perfect.
