Automate Cybersecurity Tasks with Python

Python at the level a security analyst actually needs it — not to build web apps, but to automate the repetitive parts of the job: parsing logs, cleaning input, checking against an allow list, updating a file. My RAN background already uses Python + tshark for protocol validation; on this page I walk through the allow-list algorithm I built during the course.

Why Python matters in security

Python is the SOC’s Swiss-army knife: readable syntax, cross-platform, an enormous standard library, and near-universal presence in modern security tooling. Analysts use it to automate the tasks that would otherwise burn hours a day — log parsing, IoC lookups, allow/deny-list updates, ticket enrichment, quick data-cleaning.

Types and variables

  • Data types: int, float, str, bool, None.
  • Variables — assignment, type conversion (int(), str(), float()), comments with #.
  • Output: print(), string concatenation with +, f-strings f"...".
  • Input from the user with input().
  • Arithmetic: + - * / // % **. String ops: +, *, membership in.

Control flow

  • Conditionals: if / elif / else. Operators == != < <= > >=. Logical and, or, not.
  • Loops: for x in iterable:, while cond:. range(start, stop, step), break, continue.

Functions and scope

  • def name(args): ... return value. Positional / keyword args, default values, docstrings.
  • Scope — local vs global; parameter passing by reference for mutable objects (lists, dicts) and by value for immutable (int, str, tuple).
  • Built-ins I use often: len(), type(), int(), str(), input(), sum(), min(), max(), sorted(), enumerate().

Strings and lists

  • Strings: indexing (s[0]), slicing (s[2:5]), len(), .lower(), .upper(), .strip(), .split(sep), .replace(a,b), .startswith(), .endswith(), .find(), membership with in.
  • Lists: creation [1,2,3], indexing, slicing, .append(), .remove(), .insert(), .pop(), .sort(), .reverse().
  • Dicts ({key: value}) and tuples ((a,b,c)) at working level.

Regular expressions (regex)

  • re.search(pattern, string) — find first match.
  • re.findall(pattern, string) — return all matches.
  • re.sub(pattern, replacement, string).
  • Common patterns: \d (digit), \w (word char), \s (whitespace), ., *, +, ?, character classes [abc], groups (...).
  • Analyst use: extract IPs, timestamps, usernames from log lines.

File I/O

The open() function; modes "r" (read), "w" (write / overwrite), "a" (append). Always use the with statement so the file is safely closed:

with open("file.txt", "r") as f:
    data = f.read()

Read patterns: .read() (whole file to string), .readlines() (list of lines), or iterate line-by-line. Write: .write().

Errors and debugging

  • Common exceptions: SyntaxError, NameError, TypeError, ValueError, IndexError, KeyError, FileNotFoundError.
  • Add print() statements to trace execution when needed.

Deliverable I produced

Update an allow list of IP addresses — end-to-end algorithm

Scenario: at the organisation, access to restricted content is controlled with an allow list of IP addresses in allow_list.txt. A separate remove_list variable identifies IPs that should no longer have access. I built a Python algorithm that automates updating the allow list.

Step 1 — open the file:

import_file = "allow_list.txt"

with open(import_file, "r") as file:
    # file operations go here
    ...

Why: the with statement paired with open() guarantees the file is closed on exit, even if an error occurs. The "r" argument opens the file for reading. The as keyword binds the file object to a variable (file) for the block.

Step 2 — read the file into a string:

with open(import_file, "r") as file:
    ip_addresses = file.read()

Why: .read() converts the file’s contents into a single string I can then split.

Step 3 — convert the string into a list:

ip_addresses = ip_addresses.split()

Why: .split() with no argument splits on whitespace, turning the whitespace-separated string of IPs into a Python list — a list is what I can call .remove() on later.

Step 4 — iterate through the remove list and remove matches from the allow list:

for element in remove_list:
    if element in ip_addresses:
        ip_addresses.remove(element)

Why: the for loop walks every IP in remove_list. The inner if is important — calling .remove() on a value not in the list raises ValueError. Checking membership with in avoids that.

Step 5 — convert the list back to a string and overwrite the file:

ip_addresses = "\n".join(ip_addresses)

with open(import_file, "w") as file:
    file.write(ip_addresses)

Why: .join() combines all list items into a single string using the separator (I used "\n" so each IP lands on its own line). Opening the file with "w" mode writes over its contents. .write() replaces the file with the updated string. The restricted content is no longer reachable by the removed IPs.

Complete function I wrote:

def update_allow_list(import_file, remove_list):
    with open(import_file, "r") as file:
        ip_addresses = file.read()

    ip_addresses = ip_addresses.split()

    for element in remove_list:
        if element in ip_addresses:
            ip_addresses.remove(element)

    ip_addresses = "\n".join(ip_addresses)

    with open(import_file, "w") as file:
        file.write(ip_addresses)

Concept: this same pattern (read → parse → mutate → write back) is exactly how SOCs update firewall block-lists, DNS deny-lists, EDR exclusion lists.

Pitfalls I stay aware of

  • Calling .remove() on a missing element — raises ValueError; always guard with if x in list: first.
  • Forgetting the with statement — the file stays open, holding a handle; on many hosts you’ll eventually hit a file-descriptor limit or corrupt the file.
  • Using "w" instead of "a" — "w" overwrites; if I meant to append and used "w", I’ve just erased the file.
  • Reading a huge file with .read() — loads the whole thing into memory. For big logs iterate line-by-line instead.
  • String vs list confusion — .remove() works on lists but not strings; if I skip the .split() step the algorithm breaks silently.
  • Not writing docstrings — a script another analyst has to inherit is only as useful as its documentation.

Additional Python concepts I know

  • Package manager (pip) — installs external packages: pip install requests for HTTP calls, pip install pyshark for packet analysis.
  • Python Standard Library — the modules that ship with Python itself: os, sys, re, datetime, ipaddress, hashlib, csv, json, subprocess. Enough on its own for most SOC scripts.
  • PEP 8 style guide — the community style guide for Python code (four-space indentation, snake_case names, 79-char lines). Following it makes scripts easier for other analysts to read and audit.
  • Indentation — Python uses whitespace to define code blocks. Inconsistent indentation raises IndentationError. Four spaces per level is the convention.
  • Built-in function — a function that comes with Python and needs no import (e.g. len(), print(), type()). User-defined function — a function I define with def.
  • Argument (Python) — a value passed into a function call. Options — command-line flags (e.g. --input file.txt) parsed with argparse.
  • Return statement — the return keyword hands a value back out of a function to the caller.
  • Global variable vs local variable — global lives at module scope; local lives only inside its function. Rely on locals; globals make code harder to reason about.
  • Loop condition — the expression a while loop checks each iteration; false ends the loop. Loop variable — the name that takes each value in a for loop.
  • Iterative statement — another name for a loop (for / while).
  • Conditional statement — if / elif / else.
  • Data types by name — integer (whole number), float (decimal), string (text), Boolean (True / False), list, tuple, dictionary (key-value pairs), set, date and time (via datetime).
  • Key-value pair — the element of a dictionary; {"user": "alice", "ip": "10.0.0.5"}.
  • Bracket notation — using [] to index lists (lst[0]) or access dict values (d["key"]).
  • Substring — a slice of a string, obtained via s[a:b].
  • List concatenation — joining lists with + or extend().
  • Immutable vs mutable — strings and tuples are immutable (can’t be changed in place); lists and dicts are mutable. Matters when passing to functions.
  • Automation — the reason security teams use Python at all — codify a repeatable process so it doesn’t need a human every time.

Error / exception types I recognise

  • SyntaxError — the code doesn’t parse (missing colon, unbalanced parenthesis).
  • NameError — using a variable that isn’t defined.
  • TypeError — operation on wrong type (adding a string to an int).
  • ValueError — right type but wrong value (int("abc")).
  • IndexError — list index out of range.
  • KeyError — missing dictionary key.
  • FileNotFoundError — the file path doesn’t exist.
  • Logic error — the code runs cleanly but produces the wrong result; caught only by testing / review, not by the interpreter.
