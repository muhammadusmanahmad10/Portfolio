MATLAB Flight-Test Analysis Scripts

Every flight produces hours of raw log data across multiple metrics. To turn that into a repeatable per-flight analysis story I built a MATLAB script set that ingests the aircard logs, aligns them against aircraft attitude, and produces a standard plot pack and KPI table used in every executive report. The scripts replace hours of manual inspection and let the engineering work focus on root-cause, not data-wrangling.

MATLAB RF metrics ingest PCI / serving-cell timeline Attitude overlay Mobility event markers

Inputs the scripts ingest

  • Aircard log — per-TTI UE measurement reports (RSRP/RSRQ/RSSI/SINR per branch, CQI, MCS, rank/PMI, BLER UL/DL, serving PCI, neighbour PCI list, PUSCH power/headroom, RLF cause codes).
  • Aircraft telemetry — altitude, latitude/longitude, groundspeed, heading, roll, pitch, yaw at sub-second cadence.
  • Mobility log — A3 trigger times, HO commands, HO complete, re-establishment attempts, RLF timestamps.

Standard plot pack produced per flight

  1. Altitude + roll + bank over time (always top panel — context).
  2. Serving-cell / PCI timeline (stepped) with HO events annotated.
  3. RSRP / RSRQ / RSSI / SINR per branch (V and H), two plots.
  4. CQI / MCS / rank per codeword.
  5. BLER UL / DL.
  6. DL / UL throughput with scheduled RBs overlay.
  7. PUSCH power and headroom.
  8. Mobility event markers — A3 trigger, HO Cmd, HO Cmp, Re-est Req, Re-est Cmp, RLF — as vertical lines.
  9. Flight track on a map coloured by SINR.

KPI table generated per flight

  • Connected-time % — UE in RRC_CONNECTED vs flight duration.
  • Available-time % — usable radio + data plane available.
  • Handover-failure % — failed HO attempts / total HO attempts.
  • Connection-setup-failure %.
  • Avg / max DL throughput, avg / max UL throughput.
  • Counts: RLF total, RLF by cause (T310 / RLC / MAC-RA), re-establishment-failure, HO-failure.

These feed directly into the executive report — see Flight KPI & Executive Reporting.

Design choices I locked in

  • Time alignment first. All logs are aligned to a common timestamp before any plotting. A misaligned telemetry clock makes attitude-vs-SINR analysis useless.
  • Branch-per-branch plotting. V and H branches are always separated; the average hides the branch-asymmetry cases.
  • Event markers on every panel. HO and RLF markers propagate to every plot so the eye follows them automatically.
  • Standard output filename pattern — flight_YYYY-MM-DD_route_tailnumber.pdf — so files are sortable and searchable years later.
  • One function per plot — makes it easy to add a new panel without touching the others.

What the scripts replaced

  • Manual CSV trimming in Excel — too slow for multi-hour flights.
  • Inconsistent plots per analyst — the standard plot pack is the same every time.
  • Missed attitude-correlation findings — by overlaying attitude on every plot, bank-angle events can’t be mistaken for network faults.
