5G System Architecture & Interfaces

5G replaces LTE's "boxes and tunnels" with a Service-Based Architecture (SBA) in the core — every function is an independent Network Function (NF) exposing services over HTTP/2. The NG-RAN (gNB / ng-eNB) connects to the 5G Core (5GC) via standardized reference points N1–N6, and the core NFs talk to each other over the SBA bus. Knowing which NF owns what — and which interface carries which procedure — is how I navigate every cross-team escalation.

The full picture

Network Functions — who does what, in plain words

NF (full form)In plain words
AMF — Access & Mobility Management FunctionThe UE’s "front door" to the core. Terminates NAS, handles registration, mobility, paging and access authentication (with AUSF). It’s what sits on N1 (to the UE) and N2 (to the gNB).
SMF — Session Management FunctionThe function that sets up and tears down the data session (PDU session) — assigns the UE its IP address and drives the UPF over N4 (PFCP) on how to forward the traffic.
UPF — User Plane FunctionThe actual data-forwarding box. Anchors the GTP-U tunnel from the gNB (N3), pushes the UE’s traffic out to the Data Network (N6), enforces QoS and the rules SMF gave it.
AUSF — Authentication Server FunctionThe authenticator. Runs 5G-AKA / EAP-AKA′ against the UE’s credentials on behalf of the home network.
UDM / UDR — Unified Data Management / RepositoryThe subscriber database. UDM is the service layer that serves auth/subscription data to AMF/SMF/AUSF; UDR is the data layer underneath (where profiles, policy and app data live).
PCF — Policy Control FunctionThe QoS / charging / slice rulebook. Decides what QoS, charging and slice policies should apply, and pushes them to SMF (N7) and AMF. Policy page →
NRF — Network Repository FunctionThe 5G core’s service registry / "phone book". Every NF registers itself with the NRF, and other NFs use it to discover who is currently available.
NSSF — Network Slice Selection FunctionThe slice picker. At registration it tells the network which slice (S-NSSAI) and which AMF set should serve this UE.
NEF — Network Exposure FunctionThe safe API gateway that exposes 5G core capabilities to external Application Functions (AFs) without giving them direct access to the core.
CHF — Charging FunctionThe billing engine. Handles online and offline charging (the 5G replacement for LTE’s OCS/OFCS); SMF talks to it over N40.
NWDAF — Network Data Analytics FunctionThe analytics / ML brain of the core. Collects data from other NFs and feeds insights back (load balancing, slice selection, anomaly detection, mobility prediction).
SMSF · BSF · LMF — SMS Function / Binding Support Function / Location Management FunctionSMSF carries SMS over NAS; BSF is the PCF-binding helper (so other NFs find the right PCF for a given session); LMF is the positioning brain — computes where the UE is for emergency services (see E911).

Service-Based Architecture (SBA) in one paragraph

Inside the core, NFs no longer use Diameter or point-to-point reference points only — they expose services (e.g. Namf_Communication, Nsmf_PDUSession, Npcf_SMPolicyControl) over HTTP/2 + JSON, and find each other through the NRF. Reference-point notation (N11, N7, N8, …) and service notation (Namf, Nsmf, Npcf, …) describe the same conversations from two angles. This is why a 5G core can scale and evolve like a cloud-native system — and why understanding the NF/interface map matters for debugging anything that crosses the RAN/core boundary.

How I use this in my work

Most cross-domain incidents I escalate live exactly on this map. The AMF relative-capacity attach failure sat on N2 between gNB and AMF; the slice / QoS-flow issues trace back to PCF→SMF→UPF rule installation; E911 location rides AMF↔LMF↔GMLC. Knowing the right NF and interface lets me hand a precise, evidence-backed case to the right team in one shot — instead of "the core isn't working."
