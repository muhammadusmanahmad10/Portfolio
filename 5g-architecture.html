5G System Architecture & Interfaces

5G replaces LTE's "boxes and tunnels" with a Service-Based Architecture (SBA) in the core — every function is an independent Network Function (NF) exposing services over HTTP/2. The NG-RAN (gNB / ng-eNB) connects to the 5G Core (5GC) via standardized reference points N1–N6, and the core NFs talk to each other over the SBA bus. Knowing which NF owns what — and which interface carries which procedure — is how I navigate every cross-team escalation.

Service-Based Architecture (SBA) in one paragraph

Inside the core, NFs no longer use Diameter or point-to-point reference points only — they expose services (e.g. Namf_Communication, Nsmf_PDUSession, Npcf_SMPolicyControl) over HTTP/2 + JSON, and find each other through the NRF. Reference-point notation (N11, N7, N8, …) and service notation (Namf, Nsmf, Npcf, …) describe the same conversations from two angles. This is why a 5G core can scale and evolve like a cloud-native system — and why understanding the NF/interface map matters for debugging anything that crosses the RAN/core boundary.

How I use this in my work

Most cross-domain incidents I escalate live exactly on this map. The AMF relative-capacity attach failure sat on N2 between gNB and AMF; the slice / QoS-flow issues trace back to PCF→SMF→UPF rule installation; E911 location rides AMF↔LMF↔GMLC. Knowing the right NF and interface lets me hand a precise, evidence-backed case to the right team in one shot — instead of "the core isn't working."
