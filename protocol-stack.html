Protocols · Radio Stack & TCP/IP Model

Protocol Stack: Radio Layers + TCP/IP

Every byte a UE sends crosses two stacks: the radio stack (SDAP / PDCP / RLC / MAC / PHY) that handles the air interface, and the TCP/IP model (Link / Internet / Transport / Application) that delivers it end-to-end. Understanding what each layer is responsible for is how I localize a fault — is it RF? MAC scheduling? RLC retransmission? IP routing? TCP backoff? The layer points to the team.

The NR radio stack — control plane & user plane

What each radio layer actually does

Layer (full form)PurposeKey behaviour
NAS — Non-Access StratumThe UE’s conversation with the core (AMF), riding through the gNB as a passenger. Used for registration, authentication, security and asking for a data session.Registration, security, PDU-session control. Attach flow →
RRC — Radio Resource ControlThe UE’s conversation with the gNB about radio resources — "which cell to camp on, which beam to use, when to hand over, which bearers to set up".Cell selection, measurements, handover commands (RRCReconfiguration), SRB/DRB setup, security mode.
SDAP — Service Data Adaptation Protocol (NR-only, user plane)The QoS sorter: takes each user packet and puts it on the right Data Radio Bearer based on its 5QI. The 5G replacement for LTE’s static bearer model.Marks & routes packets to the right DRB based on 5QI.
PDCP — Packet Data Convergence ProtocolThe per-bearer security + housekeeping layer: encrypts, integrity-protects, compresses headers using ROHC (Robust Header Compression), numbers and re-orders packets so they arrive once and in order.Header compression, ciphering & integrity (with KgNB-derived keys), sequence numbering, in-order delivery, ARQ-status assistance on handover.
RLC — Radio Link ControlThe reliability layer: cuts big packets into the size the air can carry, reassembles them on the other side, and retransmits anything that gets lost (in AM mode).Three modes:
  • TM (Transparent Mode) — no header, no segmentation, no retransmission. Used for very small, control-only flows where RLC just passes the packet straight through (e.g. paging, BCCH).
  • UM (Unacknowledged Mode) — segments/reassembles and reorders, but no retransmission. Good for delay-sensitive traffic like VoNR where a late packet is worse than a lost one.
  • AM (Acknowledged Mode, with ARQ) — segments/reassembles, reorders, and retransmits anything lost based on STATUS reports from the peer. Used for reliability-sensitive traffic (TCP data, signalling SRBs).
MAC — Medium Access ControlThe scheduler and traffic cop: decides which UE gets which time/frequency resources on each slot, runs fast retransmissions (HARQ), and multiplexes logical channels onto the shared transport.Logical-to-transport channel mapping, dynamic scheduling, HARQ (Stop-and-Wait per process, ACK/NACK feedback), DRX / CQI handling.
PHY — Physical Layer (L1)The radio itself: takes the coded, modulated bits and actually transmits / receives them as OFDM symbols over the air.SSB, PDCCH, PDSCH/PUSCH, PUCCH, PRACH; reference signals; beam management. PHY page →
💡HARQ vs ARQ — the difference I always check. HARQ at MAC is fast, per-process, with soft combining at PHY — the first line of retransmission. ARQ at RLC-AM is slower and reliability-oriented — the second line for what HARQ couldn't recover. A "throughput drop" with high HARQ retransmissions usually means RF/MCS; rising RLC retransmissions usually mean something more persistent in the link or scheduler.

AS vs NAS — and what 5GMM / 5GSM are

The signalling between a UE and the network splits cleanly into two halves, based on who the UE is actually talking to:

  • AS — Access Stratum. The UE’s conversation with the gNB about the radio: cell selection, beams, bearers, security on the air. In NR this is RRC + PDCP + RLC + MAC + PHY. Everything in the "radio stack" diagram above is the AS.
  • NAS — Non-Access Stratum. The UE’s conversation with the core (AMF / SMF), going through the gNB as a passenger inside RRC. The gNB doesn’t read it — it just forwards it. NAS itself splits further into two sub-protocols:
    • 5GMM — 5G Mobility Management (UE ↔ AMF). Handles registration, authentication, security mode, identity, paging, deregistration, mobility/tracking-area updates. Messages like Registration Request / Accept, Authentication Request, Security Mode Command, Service Request.
    • 5GSM — 5G Session Management (UE ↔ SMF, via the AMF). Handles PDU sessions: bringing them up, modifying QoS, tearing them down, IP-address assignment. Messages like PDU Session Establishment Request / Accept, PDU Session Modification, PDU Session Release.

In one line: AS is everything about the radio between UE and gNB; NAS is everything between the UE and the core, and inside NAS, 5GMM is "am I registered and mobile?" while 5GSM is "do I have a data session?". The two NAS halves are defined in TS 24.501.

The TCP/IP model — the other stack

Four layers

LayerWhat it does
ApplicationHTTP, SIP, DNS, FTP, RTP — the actual user-visible protocols.
TransportTCP (reliable, ordered, congestion control), UDP (unordered, lightweight), SCTP (used by NGAP, XnAP).
Internet (Network)IP routing & addressing (IPv4/IPv6), ICMP, IPsec.
LinkEthernet, VLAN, ARP — physical link & framing.

How it crosses 5G

  • On the air, the user's IP packet sits on top of SDAP → PDCP → RLC → MAC → PHY.
  • From the gNB to UPF over N3 the IP packet is tunnelled in GTP-U over UDP/IP.
  • NGAP (N2) and XnAP run on SCTP/IP; PFCP (N4) on UDP/IP; SBA on HTTP/2 (TCP).
  • MTU matters: tunnel overhead (GTP-U + UDP/IP) can fragment user packets — I check MTU on backhaul whenever throughput collapses without obvious RF cause.
  • TCP behaviour on the radio: a single packet loss triggers TCP fastRetransmit and reduces cwnd — which is why L4S/ECN matter for low-latency, low-loss scalable throughput (see load & stress).

How I use it in troubleshooting

  • Symptom: high latency on data. Check RLC-AM retransmissions and MAC HARQ. If clean, suspect TCP behaviour (cwnd collapse) or backhaul.
  • Symptom: voice clips, data OK. RTP/SIP issue at Application; or 5QI/QoS-flow mapping wrong at SDAP. QoS →
  • Symptom: NGAP/XnAP not coming up. SCTP association layer — not IP, not application. Transport →
  • Symptom: throughput tanks under tunnel. Check MTU vs tunnel overhead; fragmentation kills TCP.
