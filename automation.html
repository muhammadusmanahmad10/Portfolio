Python / tshark Automation Suite

Manual packet inspection is slow, inconsistent, and hard to audit. I built a suite of Python + tshark tools that read a capture, apply the same display filters an engineer would, correlate the expected signalling sequence per UE, and emit a CSV with frame numbers, IPs and copy-paste Wireshark filters plus a PASS/FAIL summary. The result: validation that's repeatable, standardised, and reviewable — not dependent on one engineer's eyes.

Pythontshark / Wireshark PCAP / PCAPNGCSV + GUI reporting Built for 5G SA lab validation

How the tools work

The four validators

1 · 5G SA Registration / PDU

Filter ngap && nas-5gs. Verifies the ordered sequence — security complete → registration → PDU session establishment — and extracts frame numbers for each NAS event. See registration page →

2 · NG Handover

Detects and correlates the three-step NG fingerprint — Handover Required (source) → Handover Notify (target) → UE Context Release (source) — per UE, with src/dst IPs. See NG HO page →

3 · Xn Handover (Path Switch)

Correlates the two-step Xn fingerprint — Path Switch Request → Path Switch Request Acknowledge — and reports "Handover Successful over XN interface". See Xn HO page →

4 · WPS-User Verifier

Extracts RRC establishment cause, 5QI/ARP, pre-emption flags, S-NSSAI/slice ID, DNN, IMEISV and evaluates WPS criteria for voice/data per UE. See WPS page →

Representative code (illustrative)

import subprocess, csv, collections

def extract(capture, display_filter, fields):
    cmd = ["tshark", "-r", capture, "-Y", display_filter, "-T", "fields"]
    for f in fields:
        cmd += ["-e", f]
    out = subprocess.run(cmd, capture_output=True, text=True).stdout
    return [line.split("\t") for line in out.splitlines()]

# NG handover: expected ordered sequence per UE
SEQ = ["HandoverRequired", "HandoverNotify", "UEContextReleaseCommand"]
rows = extract(cap, "ngap", ["frame.number","ip.src","ip.dst","ngap.procedureCode","ngap.RAN_UE_NGAP_ID"])

by_ue = collections.defaultdict(list)
for r in rows:
    by_ue[r[4]].append(r)            # group by RAN_UE_NGAP_ID

for ue, ev in by_ue.items():
    ok = is_ordered_subsequence(ev, SEQ)
    write_csv(ue, ev, status="PASS" if ok else "FAIL")   # + frames, IPs, filters
📈Each report includes the exact Wireshark display filter for every flagged frame, so a reviewer can jump straight to the packet — the automation accelerates analysis and leaves a clean audit trail.

The NGAP / NAS reference guide

Alongside the tools I authored a consolidated NGAP/NAS reference guide covering the full UE lifecycle — attach, registration, security, context setup, PDU session establishment, QoS & slice handling, paging & idle mode, session release, deregistration, and handover. For each message it documents:

  • Direction & purpose, and exactly what you can see in the AMF logs (key IEs, NAS-PDU details, SCTP info)
  • What it means for RAN validation, plus a per-message validation checklist
  • A lookup index: which message carries IMSI/SUPI, GUTI/TMSI, UE IDs, NAS security header/MAC/sequence, NR-CGI & TAI, slice info, QoS flows, UPF IPs/TEIDs, ePCO (DNS, P-CSCF), paging identity, DRB mapping/PDCP status, release causes and timers
  • Source↔Target transparent-container decoding for RRC continuity & DRB mapping, PDCP SN size / UL-DL SN / HFN per DRB for data-integrity checks across handover
  • Optional/enrichment notes: ePCO TLVs, DRB-to-QFI mapping, AUSF/AMF AKA correlation (XRES*/HRES*), NGAP procedure codes/criticality, NAS timers (T3512, T3502, T3560), reject causes, paging-response KPIs, SCTP stream usage

It also documents the less-common messages that show up in AMF logs (PDU session resource modify, UE context suspend/resume for RRC-inactive, AMF configuration update, NG Setup, error indication, reset/reset-ack, NAS service/registration reject, notification, policy update). Aligned to TS 24.501, TS 38.413, TS 23.502, it gives any validation engineer a single place to find which message holds the field they need, what it means, and how to validate it.

Operations automation — Excel / VBA macros

Beyond the lab Python suite, I built a set of Excel/VBA macros that turned high-volume, repetitive integration tasks into one-click operations — saving hours per activity and eliminating manual-typing mistakes that were the actual cause of most rollback incidents.

RET
RET Configuration macro After powering on RET ports, the site engineer confirmed which jumper went to which layer. The macro scanned the ALD output for RET serial numbers, matched each serial to the layer the engineer confirmed, looked up the planned tilt from the RF data sheet, and emitted the full ADD RET command set for the site. One click instead of dozens of manual lookups; eliminated the wrong-tilt-on-wrong-sector class of error.
Bulk CR
Bulk CR opening (30+ CRs → Outlook) Before starting an integration window we had to open 30+ Change Requests with NOC. The macro reads each CR row from Excel, opens an Outlook draft with the CR info in the body, sets To/CC recipients, sets the email subject to the CR number, and sends. All 30+ notification emails go out within a minute — manually this used to take 30+ minutes of error-prone copy-paste.
Xn/X2
Xn / X2 interface creation macro For peer-site interface setup, the macro generated the scripts to create the SCTPPEER for the peer gNB/eNB and add it to the correct EPGROUP for the Xn or X2 interface. Removes a frequent source of mis-typed peer IPs and port mappings that block interface bring-up.
Health
Site health-check verification macro After integration, the macro reads the site's running parameters and cross-checks them against the MTAC reference health-check sheet (which says, parameter by parameter, what value each should hold). Mismatches are flagged automatically — what used to be a multi-hour manual audit becomes seconds.
Pre/Post
Pre/Post cell-status verification macro Compares pre-activity and post-activity cell-status reports across the whole network; flags any cell whose state changed unexpectedly — e.g. a deactivated cell that's now active, or an active cell that's been deactivated by accident. Catches "wrong cell touched" errors before they hit a customer escalation.
💡Common pattern: each macro takes a repetitive, error-prone task humans were doing dozens of times per activity, and turns it into a one-click operation backed by the planning data we already had in Excel. The win isn't just time — it's the elimination of the manual-typing class of integration faults.

Impact

Together, the suite turns slow, manual, error-prone PCAP review into a repeatable, standardized PASS/FAIL with a built-in audit trail — and the reference guide makes the team's signalling knowledge reusable instead of locked in one person's head. Both reduce ramp-up time for new validation engineers and improve consistency across regression cycles.
