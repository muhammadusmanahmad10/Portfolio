RAN Troubleshooting Case Library

During large-scale multi-RAT integration I documented real field faults — symptom, investigation, root cause, and resolution — and published them on the equipment vendor's official engineering case portal so other engineers could resolve the same issue faster. Below is a representative selection. Each is a genuine site incident I diagnosed and closed, organised by failure domain.

45+ published cases 2G / 3G / 4G / 5G NSA / 5G SA Integration · Hardware · Software · Transport

Integration & configuration conflicts

A1
GU site went to mediation after new L700 integration as non-SDR Integrating L700 as a non-SDR config pushed the GU site into mediation. Resolved by correcting the working mode extension of the node.

RF & cell-setup failures

B1
U900 cell setup failed — frequency overlapped in G900 MAGROUP The U900 cell wouldn't set up because its frequency overlapped a frequency already in the G900 MA-group. Re-planned the frequency allocation to remove the overlap.
B2
G900 RRU not coming up in a CPRI MUX scenario In a CPRI MUX (multiplexed fronthaul) topology the G900 RRU failed to come up. Traced to the CPRI mux chain/topology configuration and corrected the port mapping.
B3
UMTS cells down due to baseband equipment not found (small-cell variant) 3G (UMTS) cells on a small-cell site stayed down because the cell objects had no BASEBANDEQM binding and the binding command wasn’t exposed in the LMT package available. Activated the binding from CME and the cells came up. (See the integration page for the detailed write-up.)
B4
No 5G NSA users due to EN-DC anchor relation with LTE not created properly (ExternalCell) The new site was 5G NSA, so UEs could only reach the 5G cell via EN-DC anchored on an LTE cell. UEs weren’t showing up on the 5G cell because the EN-DC anchor relation with the LTE anchor was not created properly — the ExternalCell configuration that represents the LTE anchor cell from the NR side was incorrect, so the anchor relation between LTE and NR never formed and the LTE anchor couldn’t add the NR cell as the SCG. Corrected the ExternalCell configuration to establish the EN-DC anchor relation; SCG-add succeeded and UEs began camping on the 5G cell via the LTE anchor.
B5
No 5G users camping due to anchoring configuration issue at the neighbouring site 5G NSA UEs weren’t camping on the new NR cell because the LTE anchor neighbour configuration was wrong, breaking the EN-DC anchor. Corrected the neighbouring LTE site’s anchor configuration to enable EN-DC attach.
B6
5CC traffic drop after TDD Massive MIMO due to wrong SCCFreq / EUTRANINTERNFREQ configuration A 5-carrier-aggregation (5CC) configuration lost traffic after a TDD Massive-MIMO change. Cause was incorrect SCCFreq (secondary-cell-group frequency) and EUTRANINTERNFREQ (internal-frequency relation) parameters. Re-aligned both to the planned values and 5CC throughput recovered.
B7
LTE end — no voice and no data traffic after a TAC change After a Tracking Area Code change on an LTE site, voice and data traffic dropped to zero because the new TAC wasn’t propagated into the core. Aligned the TAC at the core side and re-activated; traffic recovered.
B8
NB-IoT cells not coming up due to wrong MME capability configuration NB-IoT cells stayed down after activation. Root cause was an MME capability configuration that didn’t advertise NB-IoT support, so the S1 setup never accepted the cell. Updated the MME capability configuration and NB-IoT cells came up.
B9
Weak-coverage issue after 5G deployment due to a power setting After a fresh 5G site went live, coverage came out weaker than plan. Root-caused to an incorrect transmit-power setting on the new NR carrier; corrected to the planned RF design and coverage met the target.

Transport & security

C1
High TNL failures on a 5G site due to VLAN overlap with LTE traffic A 5G site showed a spike in Transport Network Layer (TNL) failures right after activation. Investigation traced the cause to a VLAN overlap: the VLAN tag used by 5G traffic was already in use by LTE on the same transport, so frames were mis-routed. Re-assigned the 5G transport to a non-overlapping VLAN and TNL failures dropped to zero.
C2
S1 interface alarm after migrating to a third-party PKI server Migrating to a third-party PKI server broke the S1 interface (certificate / IPsec trust path). Re-established the security / certificate configuration so S1 recovered — an early parallel to the 5G IPsec/cert work I do now.
C3
S1 abnormal due to wrong IKE proposal configuration S1 interface stayed abnormal because the IKE proposal (encryption / integrity / DH group) didn’t align with the peer’s expectation, so IKE_SA_INIT was rejected before IPsec could come up. Re-aligned the IKE proposal to the agreed set and S1 came healthy.

Software & upgrade

D1
Software-package download failed — incorrect FTP parameter settings Package download failed due to wrong FTP parameters. Corrected the FTP server / credentials / path settings to complete the download.
D2
LMT limited-packages issue after software upgrade Post-upgrade, the local maintenance terminal showed a limited-packages state. Restored the correct package set so full LMT functionality returned.

Why this matters

Publishing these cases did two things: it closed real outages across thousands of integration sites, and it turned each fix into reusable knowledge for the wider engineering community. The throughline to my current 5G SA work is the same diagnostic method — separate symptom from cause, prove the root cause with logs/alarms before acting, and document it so the next engineer is faster.
