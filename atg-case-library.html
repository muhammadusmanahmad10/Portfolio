ATG Flight-Test Case Library

A running catalogue of real investigations I ran against live 800 MHz LTE ATG flight-test data and aircard logs. Each case follows the same structure — Symptom → Evidence → Diagnostic reasoning → Root cause → Outcome / escalation — so another engineer can lift it and reuse it. Where I recommended / validated a parameter change, I say so; where I escalated to the vendor, I say that too. The phrasing is deliberately honest about what I did vs what the vendor owned.

Case A — Post-handover CQI / MCS recovery lag

Symptom
After a successful handover, DL / UL throughput visibly dipped for several seconds even though RSRP / SINR had already recovered on the target cell. KPIs showed handover-success but user-experienced throughput dropped.
Evidence
MATLAB plot pack overlay — SINR recovers to steady-state within <1 s of HO complete, but CQI reports stayed depressed for 3–5 s and MCS tracked the CQI, not the SINR. BLER was normal during the depressed-MCS window.
Diagnostic reasoning
The radio is healthy (SINR + BLER tell that story), so the shortfall isn’t coverage or interference. The shortfall maps 1-to-1 to CQI/MCS trajectory. That’s a vendor OLLA / CQI-filtering issue in the post-HO window — the filter is too conservative after the handover reset.
Root cause
Suspected scheduler-side CQI filter reset / OLLA reinitialisation at HO. Not a radio fault.
Outcome / escalation
Escalated to vendor with the labelled plot pack and the post-HO window highlighted. Documented impact on executive KPIs (avg DL throughput). Tracked across loads for fix validation (Vendor Defect Tracking).

Takeaway: post-HO throughput depression with healthy SINR is a scheduler / OLLA post-reset story, not a radio story.

Case B — Sustained high UL & DL BLER tracked to scheduler

Symptom
Sustained PUSCH and PDSCH BLER well above the OLLA target on multiple flights, with RSRP and SINR in the normal operating range.
Evidence
SINR stable — no interference spike; MCS running at values that the local SINR did not support (link adaptation was not matching conditions); UL power headroom was sufficient. HARQ residual BLER was correspondingly high.
Diagnostic reasoning
If MCS is consistently too aggressive for the SINR, OLLA isn’t doing its job. Pattern seen on both DL and UL → points to a scheduler behaviour, not a per-UE problem.
Root cause
Suspected vendor scheduler / OLLA target misconfiguration — too aggressive an initial MCS for the observed CQI mapping.
Outcome / escalation
Escalated to vendor with evidence: SINR trace, MCS trace, BLER trace, and the per-codeword gap for 2C2L. Did not change the vendor’s scheduler myself.

Takeaway: sustained BLER that doesn’t respond to SINR is a scheduler problem, not a radio problem. The place to file the defect is the scheduler team.

Case C — Erratic DL throughput with stable SINR

Symptom
DL throughput was erratic (large swings minute-to-minute) while SINR and radio metrics were stable. User experience inconsistent.
Evidence
SINR tight around a stable value; RSRP steady; MCS oscillating between the OLLA limits; DL buffer occupancy also fluctuating; BLER only moderately moving.
Diagnostic reasoning
Radio is quiet, so the throughput swings don’t come from the air. MCS oscillation + buffer occupancy swing + stable SINR = scheduler decision volatility, not radio volatility.
Root cause
Suspected vendor scheduler behaviour — OLLA / proportional-fair volatility or an interaction with per-UE PRB allocation.
Outcome / escalation
Escalated to vendor with the SINR-vs-throughput overlay traces and MCS oscillation evidence.

Takeaway: erratic throughput with stable SINR and healthy BLER points above the radio. The diagnostic is the correlation: throughput variance that doesn’t track radio variance.

Case D — TCP throughput drop after iperf-server migration (transport, not radio)

Symptom
After the iperf server was migrated from Denver to Melbourne, DL TCP throughput dropped from ~6 Mbps to ~2 Mbps. Initial interpretation: radio regression on the new load.
Evidence
  • DL buffer occupancy ~5% — link occupancy near-zero; eNB was starved of data to send.
  • MCS unchanged between pre- and post-migration runs.
  • Rank-2 (2C2L) usage reduced — a secondary effect of lower offered load.
  • UDP iperf to Melbourne delivered ~8 Mbps over the same path — the radio could carry the data.
Diagnostic reasoning
TCP throughput ≈ window / RTT. The RTT from the aircraft to Melbourne is ~160 ms vs ~40 ms to Denver. With the default UE TCP window, throughput is bandwidth-delay-product limited, not radio limited. Low link occupancy confirms the eNB is being under-fed by transport.
Root cause
Transport, not radio. BDP cap at the new RTT with the default TCP window.
Outcome / recommendation
Recommended larger TCP receive window, parallel streams for user-level testing, and co-locating the iperf server near the test region for radio comparisons. See Radio-Transport Boundary.

Takeaway: buffer occupancy + MCS stability + UDP sanity test are the three tells that separate radio from transport. One flight-trace analysis saved weeks of chasing a non-existent radio regression.

Case E — No-dominance coverage-hole mobility collapse

Symptom
A ~2-minute region where the UE sat with multiple cells at near-equal RSRP (no dominant server). Continuous uplink RLFs (MAC-RA and RLC max-ReTx) and re-establishment failures (T311 expiry) with SIB-acquisition failures on a mod-3-conflicted PCI.
Evidence
Attitude flat — not a bank-angle event. RSRPs within 2 dB of each other on 3–4 cells; none strong enough to dominate; SINR depressed throughout the region; RLF cause-code mix skewed toward MAC-RA and RLC max-ReTx; SIB-acquisition failures on the PCI pair with mod-3 conflict.
Diagnostic reasoning
No-dominance zones on a single-frequency network cause chronic SINR depression. Mod-3 conflicts amplify it on 2-TX cells. Re-establishment fails because no candidate cell can read SIBs cleanly and no cell is strong enough to handle Msg3 PRACH reliably.
Root cause
Network geometry (no established dominance) + PCI mod-3 conflict on the near neighbour pair.
Outcome / recommendation
Recommended (a) adjust tilts / power on two cells to establish dominance, and (b) PCI re-plan to remove the mod-3 conflict. See PCI Planning for 2-TX ATG Cells.

Takeaway: no-dominance regions are a network-planning problem, not a UE problem. On a single-frequency network they’re the hardest to fix and the most expensive to leave.

Case F — Vertical-branch constant SINR deficit

Symptom
A sustained ~5 dB SINR deficit on the vertical-polarization branch with equal RSRP across V and H branches, across multiple flights and cells.
Evidence
RSRP V ≈ RSRP H (within <1 dB); SINR V < SINR H by ~5 dB consistently; rank-2 engages less often because the vertical branch caps the second layer; happens across geographic regions, not tied to specific cells.
Diagnostic reasoning
Equal RSRP but unequal SINR means the signal arrives on both branches but the noise + interference floor is higher on one. That’s a receiver-side problem, not a propagation problem. The fact that it’s the same deficit across geographic regions rules out site-specific interference.
Root cause (suspected)
Elevated noise floor / desense on the vertical receive chain on the aircard — LNA, filter, cable, or connector on that branch.
Outcome / recommendation
Recommended a bench noise-figure / sensitivity test of the vertical receive chain on the aircard hardware. Escalated with the SINR-branch evidence. See Interference vs Fade Diagnosis.

Takeaway: constant branch asymmetry with equal RSRP is a receiver chain issue. Don’t chase it in the network.

Case G — UL random-access RLFs tied to PRACH for ATG geometry

Symptom
MAC-RA RLFs during re-establishment attempts after handover failure — the UE tries to recover on a nearby cell, PRACH fails, T311 expires, UE drops to full connection setup.
Evidence
Preamble attempts in the trace, no RAR response, retries up to preambleTransMax, MAC-RA cause emitted. The affected cells were long-range (100+ km edge), and the Doppler-equivalent speeds were cruise speeds.
Diagnostic reasoning
At 100+ km the PRACH round-trip must fit in the preamble detection window. If the configured cell-radius / format / Ncs doesn’t cover the real range, preambles miss the window. At cruise Doppler, the high-speed restricted cyclic-shift set must be on, or preambles alias.
Root cause (suspected)
PRACH configuration tuned for shorter-range / lower-Doppler scenarios than ATG actually uses.
Outcome / recommendation
Recommended verification of PRACH format (3 for 100+ km), Ncs sized for the full cell radius, cell-radius parameter honest, and HighSpeedFlag on. Where lab-reproducible, validated candidate fixes via channel-emulator setup. See UL Random Access & PRACH for ATG.

Takeaway: MAC-RA failures that only appear in cruise, not in lab, are PRACH-config stories — especially cell-radius and HighSpeedFlag.
