Multi-RAT Integration & Scripting

Across 10,000+ sites I integrated and commissioned RAN spanning 2G, 3G, 4G, 5G and NB-IoT on a single multi-mode platform. That means writing the site scripts, merging baseband, converting standalone radios to SRAN (one cabinet serving multiple technologies), expanding sector-carriers, and bringing complex radio topologies on air — through CME, local maintenance terminals, and direct CLI integration.

Multi-mode site architecture

Core configuration work — and what each actually means

OperationWhat it is & why it's done
SRAN conversionConsolidating separate single-RAT radios onto one multi-mode (Single RAN) platform so 2G/3G/4G/5G share baseband, transport and radios — cuts hardware, site visits and power.
BBU mergingCombining baseband units so multiple technologies/cells run from one BBU — frees slots and simplifies the site, but requires careful cell/clock/transport re-mapping in script.
SDR / NSDRSoftware-defined vs non-software-defined radio configs — determines whether a band can be re-purposed in software or needs hardware change.
Sector-carrier expansionAdding carriers/sectors for capacity — the script must extend cell, carrier, and resource mapping without disrupting live cells.
4T6S / Multi-RRUAdvanced radio topologies (4 transmit / 6 sector, multiple RRUs per cell) for coverage/capacity — sensitive to CPRI mapping and working-mode config.
MORAN / MOCNRAN sharing: MORAN = shared radio, separate carriers per operator; MOCN = shared carrier, multiple operators' core networks (multiple PLMNs broadcast).

How I worked

I prepared complex site scripts in CME (configuration management) and applied them via local maintenance terminals and direct CLI for on-site integration — covering refarming, rehoming, IP migration, IP security, and software/licensing updates across BTS, NodeB, eNodeB and gNodeB. Because a single script touches cells, clocks, transport and radios at once, the discipline is in validating the script against the existing config before commit — most integration incidents (see the case library) trace back to a working-mode, topology, or peer-end mismatch that a careful pre-check catches.

Field notes & common pitfalls

  • Working-mode must match the peer end. A mismatched RF-unit working mode between GU/inter-system ends is a classic conflict-alarm source.
  • Validate topology before commit. RRU network-topology/type mismatches surface as setup failures after integration.
  • Frequency/MAGROUP overlaps block cell setup — check band plans before adding U900/G900 carriers.
  • SRAN conversions touch everything at once — clock, transport, cells — so stage and verify each layer.

Sync & configuration workflow

  • Timing & sync: GPS, PTP and NTP servers for frame/phase synchronization (with PTP↔GPS fallback validated on the lab side).
  • Per-site config blocks: IP & RF configuration, board configuration, and neighbour/core configuration specifically for Xn HO and NG activity.
  • Sharing: MORAN (shared radio, separate carriers) and MOCN (shared carrier, multiple PLMNs/core networks).
  • Tech modes: 5G SA / NSA, NR UL/DL decoupling, RedCap.
